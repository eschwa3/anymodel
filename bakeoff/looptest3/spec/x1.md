## X1 — Invoice discounts (percentage + fixed), applied before tax

The `## X1` section below is a self-contained contract for one small
billing feature. Implement exactly the named public API in the named NEW
module; do not modify any existing jobsched file. New modules may import
and call existing code (`jobsched.billing`, `jobsched.utils.money`,
`jobsched.repository`, `jobsched.errors`, ...). Money is integer cents
everywhere; the rounding rule is **half-up**, applied once at finalization,
via `jobsched.utils.money.round_half_up` (the same helper
`jobsched.billing.compute_tax` already uses). Follow the repo conventions
in AGENTS.md: stdlib only, `from __future__ import annotations`, absolute
imports, raise `jobsched.errors` exceptions for anything a caller catches.

Purpose: give callers a reusable way to reduce an invoice subtotal by a
percentage and/or a fixed amount before tax is computed on the result.

New module: `jobsched/billing_discounts.py` (new file; existing files untouched).

Public contract (exact signatures):

```python
def apply_discount(subtotal_cents: int, percent_off_bp: int = 0, off_cents: int = 0) -> int
def discount_amount(subtotal_cents: int, percent_off_bp: int = 0, off_cents: int = 0) -> int
```

- `percent_off_bp` is the percentage discount in basis points (10000 = 100%).
- `off_cents` is a fixed-cents discount subtracted after the percentage step.
- `apply_discount` returns the discounted subtotal in integer cents.
- `discount_amount` returns the total cents actually removed, defined as
  `subtotal_cents - apply_discount(...)` for the same arguments.

Behaviour rules:
1. Percentage step first: the cents removed by the percentage are
   `round_half_up(subtotal_cents * percent_off_bp / 10000)` (half-up,
   same formula as `jobsched.billing.compute_tax` uses for tax).
2. Fixed step second: `net = subtotal_cents - pct_discount - off_cents`,
   then clamped at 0 — the result is never negative, even when
   `pct_discount + off_cents` exceeds `subtotal_cents`.
3. `discount_amount` must stay consistent with `apply_discount`: it is the
   clamped total removed, so a clamped result makes it smaller than
   `pct_discount + off_cents`.
4. Validation — raise `jobsched.errors.ValidationError` when any of:
   `subtotal_cents < 0`; `percent_off_bp` outside `0..10000`; `off_cents < 0`.
5. Edge cases: `percent_off_bp=0, off_cents=0` returns `subtotal_cents`
   unchanged; `percent_off_bp=10000` (100%) returns 0 regardless of
   `off_cents`; rounding example — 50% off 1001 cents removes
   `round_half_up(500.5)` = 501 cents, net 500 cents.

Existing behaviour and existing tests must keep passing; this feature only
adds a new module and changes nothing else.
